מטרות (Objectives)

  • לזהות סוג קובץ אמיתי (Magic Bytes) מול סיומת מזויפת
  • לחשב Hashes (MD5, SHA-256, SSDeep) ולחפש ב-VirusTotal
  • לחלץ Strings ולסווג ממצאים (URL/IP/Registry/API)
  • לנתח PE Headers, Imports, Sections, Entropy
  • לזהות Packers (UPX וכד') ולפרוק
  • לכתוב חוק YARA בסיסי
  • להגיע ל-Verdict (clean / suspicious / malicious) על 3 דוגמאות

הקמת VM — שלב אחר שלב (קרא קודם, בצע פעם אחת)

בצע הכל בתוך Virtual Machine. לעולם לא על המחשב האמיתי. בתוך ה-VM אתה root/Administrator — לא צריך הרשאות אדמין על המארח.

חלק 2 — יצירת Kali Linux VM (מעבדות 1, 4, 5)

  1. 2.1 הורד Kali VM מוכן
    https://www.kali.org/get-kali/#kali-virtual-machines
→ לחץ על טאב "VirtualBox"
→ לחץ "64-bit"  (~3 GB קובץ .7z)
→ המתן לסיום ההורדה
    מוכן מראש = אין צורך בהתקנה. ה-.7z מכיל דיסק VM מוכן.
  2. 2.2 חלץ את ה-.7z
    Windows: התקן 7-Zip מ-7-zip.org, לחיצה ימנית על .7z → 7-Zip → Extract Here
macOS:   התקן Keka מ-keka.io, לחיצה כפולה על ה-.7z
Linux:   sudo apt install p7zip-full; 7z x kali-linux-*.7z
תוצאה:   תיקייה עם  kali-linux-*.vbox  +  .vdi
  3. 2.3 ייבוא ל-VirtualBox
    1. פתח VirtualBox
2. תפריט: Machine → Add  (או Ctrl+A)
3. נווט לתיקייה שחילצת
4. בחר את קובץ ה-.vbox → Open
5. ה-VM מופיע ברשימה השמאלית כ-"kali-linux-..."
  4. 2.4 כוונון משאבי VM (מארח חלש)
    לחיצה ימנית על ה-VM → Settings:

System → Motherboard tab:    Base Memory = 4096 MB  (או 3072 אם המארח חלש)
System → Processor tab:      CPUs = 2
Display → Screen tab:        Video Memory = 64 MB ; בטל 3D Acceleration
Audio:                       בטל "Enable Audio"
USB:                         בחר USB 1.1 (לא 3.0)
Network → Adapter 1:         Attached to: NAT  (מאפשר אינטרנט ל-VirusTotal)

לחץ OK
  5. 2.5 הפעלה ראשונה
    לחיצה כפולה על Kali VM → המתן לטעינת שולחן העבודה
משתמש: kali
סיסמה: kali
פתח Terminal (אייקון בפינה שמאל-עליון)
הרץ:  whoami    →  אמור להציג: kali
הרץ:  sudo -v   →  הכנס "kali" → אין שגיאה = sudo עובד
    שולחן העבודה של Kali נטען. Terminal נפתח. sudo apt update מצליח.
  6. 2.6 צילום snapshot של מצב נקי
    בחלון VirtualBox של ה-VM: Machine → Take Snapshot
שם: "clean-kali"
תיאור: "Kali טרי, sudo עובד"
→ OK
    Snapshot = נקודת שמירה. אם משהו נשבר, שחזור תוך 5 שניות.

  8. שלב 8 — ניתוח PE עם pefile
    python3 <<'EOF'
import pefile

samples = ['samples/sample_A.exe', 'samples/sample_B.exe']

for sample in samples:
    print(f"\n========== {sample} ==========")
    pe = pefile.PE(sample)
    print(f"Compile Time: {pe.FILE_HEADER.TimeDateStamp}")
    print(f"Entry Point:  {hex(pe.OPTIONAL_HEADER.AddressOfEntryPoint)}")
    print(f"Image Base:   {hex(pe.OPTIONAL_HEADER.ImageBase)}")
    print(f"Subsystem:    {pe.OPTIONAL_HEADER.Subsystem}")

    print("\n-- Sections --")
    for s in pe.sections:
        name = s.Name.decode().rstrip('\x00')
        e = s.get_entropy()
        flag = " [HIGH ENTROPY!]" if e > 7.0 else ""
        print(f"  {name:8s} size={s.SizeOfRawData:8d} entropy={e:.2f}{flag}")

    print("\n-- Suspicious Imports --")
    suspicious = ['VirtualAlloc','CreateRemoteThread','WriteProcessMemory',
                  'NtUnmapViewOfSection','URLDownloadToFile','WinExec',
                  'ShellExecute','RegSetValueEx','CryptEncrypt','IsDebuggerPresent']
    if hasattr(pe, 'DIRECTORY_ENTRY_IMPORT'):
        for entry in pe.DIRECTORY_ENTRY_IMPORT:
            for imp in entry.imports:
                if imp.name and imp.name.decode() in suspicious:
                    print(f"  {entry.dll.decode()} -> {imp.name.decode()}")
EOF
    sample_B (UPX-packed) יראה סקציות UPX0/UPX1 עם Entropy > 7.5. sample_A יראה .text/.rdata/.data עם Entropy ~6.

  10. שלב 10 — חוק YARA בסיסי
    cat > output/lab1.yar <<'YARA'
rule Suspicious_PE_Imports {
    meta:
        description = "PE with multiple injection-related imports"
        author = "CyberLabs Student"
        date = "2026-04-29"
    strings:
        $imp1 = "VirtualAlloc"      ascii
        $imp2 = "CreateRemoteThread" ascii
        $imp3 = "WriteProcessMemory" ascii
        $mz   = { 4D 5A }
    condition:
        $mz at 0 and 2 of ($imp*)
}

rule UPX_Packed {
    meta:
        description = "UPX-packed PE detection"
    strings:
        $upx0 = "UPX0" ascii
        $upx1 = "UPX1" ascii
    condition:
        any of them
}
YARA

yara output/lab1.yar samples/
    החוק UPX_Packed ימצא את sample_B. החוק Suspicious_PE_Imports ימצא את sample_C (אם לא ארוז).

    נוזקות רבות מגיעות לא כ-EXE אלא כ-Word/Excel עם VBA Macros. olevba מחלץ ומסווג מאקרו אוטומטית.

olevba samples/invoice.docm | tee output/05_olevba.txt

# פלט אופייני:
# Type: OLE
# AutoExec keywords:
#   AutoOpen     -> Runs when document is opened
#   Document_Open -> Runs when document is opened
# Suspicious keywords:
#   Shell        -> May run an executable file
#   PowerShell   -> May execute PowerShell commands
#   CreateObject -> May create OLE objects
#   Open         -> May open a file
# IOCs:
#   URL          -> http://malicious.example.com/payload.exe
#   Executable file -> payload.exe

# חילוץ המאקרו עצמו
olevba --decode samples/invoice.docm

# סריקה אגרסיבית של תיקייה שלמה
oledir samples/
mraptor samples/invoice.docm
# mraptor = MS Office Macros Risk Analyzer ב-3 רמות: Suspicious / Safe / Risky
    olevba מציג AutoOpen/AutoExec, מילות מפתח חשודות, ו-IOCs (URLs, EXEs). MRAPTOR נותן verdict חד-משמעי.

    • sample_B: פריקה (UPX -d), הרצת ניתוח חוזר על הקובץ הפרוק
    • sample_C: העברה ל-Dynamic Analysis (Lab 3) ול-Memory Forensics (Lab 4)

תוצאה צפויה

  • טבלה השוואתית מלאה ל-3 דוגמאות עם Verdict מנומק
  • 10+ מחרוזות מסווגות עבור sample_C
  • 5+ Suspicious Imports מתועדים
  • UPX זוהה ב-sample_B; Entropy ו-Section names תומכים בכך
  • YARA Rules עובדים על הדוגמאות
Cross-Check ב-Sysinternals (אופציונלי):

בעבודה אמיתית כ-SOC ב-Windows, הכלי sigcheck מ-Sysinternals מבצע את שלבי 4+5+8+9 בשורה אחת:

sigcheck.exe -vt -e -h -nobanner C:\samples\sample_A.exe

פלט: Verdict חתימה + Entropy + VT + MD5/SHA1/SHA256.

במעבדה 2 נשתמש ב-Sysinternals באופן פעיל — Live Triage על תהליך חי.

Automated Sandboxes — מתי לשלוח?

אחרי Static Analysis, אם יש ספק או נדרש ניתוח דינמי בלי VM משלך — שלח ל-cloud sandbox:

  • VirusTotal — Hash + Multi-AV + Behavior summary. חינם, מהיר.
  • Any.run — Interactive sandbox עם UI חי. חינם בסיסי.
  • Hybrid Analysis — דו"חות מפורטים, IOCs, MITRE mapping. חינם.
  • Joe Sandbox — Comprehensive enterprise sandbox.

אזהרה: דוגמאות ייחודיות / ארגוניות = לא להעלות ל-cloud (דליפת מידע). השתמש ב-sandbox מקומי (Cuckoo, CAPE).

שאלות לסיכום

  1. למה Defender לא חוסם את הקבצים בתוך zip עם סיסמה?
  2. מה ההבדל בין SHA-256 ל-SSDeep, ומתי כל אחד שימושי?
  3. מדוע Entropy > 7.0 = סימן ל-Packing/Encryption?
  4. איזה Verdict היית נותן לקובץ עם 0 גילויים ב-VT אבל imports חשודים? למה?
  5. הסבר את ההבדל בין סקציות .text/.rdata/.data לבין UPX0/UPX1.
  6. כתוב חוק YARA שמזהה PE שמייבא גם InternetOpenA וגם CryptEncrypt (Ransomware Heuristic).
  7. איזה שלב במעבדה היה נחסך אם היית עובד ב-Windows עם sigcheck?

סיכום

Static PE Triage = שלב ראשון בכל חקירת נוזקה. הקובץ לא רץ — בטוח לחלוטין. הכלים file, strings, exiftool, pefile, diec, yara מספיקים ל-90% מהמקרים. UPX-packed = Verdict Suspicious מיידי. סימני VT גבוהים + Suspicious Imports = Malicious.
