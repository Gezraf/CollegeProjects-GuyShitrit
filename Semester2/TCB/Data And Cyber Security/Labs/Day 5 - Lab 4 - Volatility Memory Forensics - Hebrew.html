הקמת VM — שלב אחר שלב (קרא קודם, בצע פעם אחת)

בצע הכל בתוך Virtual Machine. לעולם לא על המחשב האמיתי. בתוך ה-VM אתה root/Administrator — לא צריך הרשאות אדמין על המארח.

חלק 1 — התקנת VirtualBox (כל מערכת הפעלה)

  1. 1.1 הורד installer
    https://www.virtualbox.org/wiki/Downloads
בחר:  Windows hosts  /  macOS / Intel hosts  /  Linux distributions
      (Mac עם Apple Silicon? השתמש ב-UTM: https://mac.getutm.app/)
  2. 1.2 הרץ installer
    Windows:   לחיצה כפולה על .exe → Next, Next, Next, Install → Finish
macOS:     לחיצה כפולה על .dmg → גרור VirtualBox ל-Applications
           → אם חסום: System Settings → Privacy → "Allow" Oracle
Linux:     sudo apt install virtualbox virtualbox-ext-pack
  3. 1.3 ודא
    פתח VirtualBox → תפריט Help → About
אמור להופיע: "Oracle VirtualBox 7.x"
    חלון VirtualBox נפתח. אין שגיאות. רשימת VM ריקה.

חלק 2 — יצירת Kali Linux VM (מעבדות 1, 4, 5)

  1. 2.1 הורד Kali VM מוכן
    https://www.kali.org/get-kali/#kali-virtual-machines
→ לחץ על טאב "VirtualBox"
→ לחץ "64-bit"  (~3 GB קובץ .7z)
→ המתן לסיום ההורדה
    מוכן מראש = אין צורך בהתקנה. ה-.7z מכיל דיסק VM מוכן.
  2. 2.2 חלץ את ה-.7z
    Windows: התקן 7-Zip מ-7-zip.org, לחיצה ימנית על .7z → 7-Zip → Extract Here
macOS:   התקן Keka מ-keka.io, לחיצה כפולה על ה-.7z
Linux:   sudo apt install p7zip-full; 7z x kali-linux-*.7z
תוצאה:   תיקייה עם  kali-linux-*.vbox  +  .vdi
  3. 2.3 ייבוא ל-VirtualBox
    1. פתח VirtualBox
2. תפריט: Machine → Add  (או Ctrl+A)
3. נווט לתיקייה שחילצת
4. בחר את קובץ ה-.vbox → Open
5. ה-VM מופיע ברשימה השמאלית כ-"kali-linux-..."
  4. 2.4 כוונון משאבי VM (מארח חלש)
    לחיצה ימנית על ה-VM → Settings:

System → Motherboard tab:    Base Memory = 4096 MB  (או 3072 אם המארח חלש)
System → Processor tab:      CPUs = 2
Display → Screen tab:        Video Memory = 64 MB ; בטל 3D Acceleration
Audio:                       בטל "Enable Audio"
USB:                         בחר USB 1.1 (לא 3.0)
Network → Adapter 1:         Attached to: NAT  (מאפשר אינטרנט ל-VirusTotal)

לחץ OK
  5. 2.5 הפעלה ראשונה
    לחיצה כפולה על Kali VM → המתן לטעינת שולחן העבודה
משתמש: kali
סיסמה: kali
פתח Terminal (אייקון בפינה שמאל-עליון)
הרץ:  whoami    →  אמור להציג: kali
הרץ:  sudo -v   →  הכנס "kali" → אין שגיאה = sudo עובד
    שולחן העבודה של Kali נטען. Terminal נפתח. sudo apt update מצליח.
  6. 2.6 צילום snapshot של מצב נקי
    בחלון VirtualBox של ה-VM: Machine → Take Snapshot
שם: "clean-kali"
תיאור: "Kali טרי, sudo עובד"
→ OK
    Snapshot = נקודת שמירה. אם משהו נשבר, שחזור תוך 5 שניות.

חלק 3 — יצירת Windows 10 VM (מעבדות 2, 3 — דלג אם רק 1,4,5)

  1. 3.1 הורד Win10 Enterprise Eval ISO
    https://www.microsoft.com/evalcenter/evaluate-windows-10-enterprise
→ הירשם (כל אימייל עובד) → בחר ISO → 64-bit English
→ ~5 GB הורדה. חינם ל-90 יום.
  2. 3.2 צור VM חדש ב-VirtualBox
    תפריט: Machine → New
Name:           Win10-Lab
Type:           Microsoft Windows
Version:        Windows 10 (64-bit)
Memory:         4096 MB
Hard disk:      Create a virtual hard disk now → VDI → Dynamically allocated → 60 GB
→ Create
  3. 3.3 חבר את ה-ISO
    Settings → Storage → Empty (אייקון CD) → לחץ אייקון CD מימין →
Choose a disk file → בחר את Win10 ISO → OK
Network → Adapter 1: NAT (לבינתיים; החלף ל-Host-Only במעבדה 3)
Display → Video Memory 128 MB
  4. 3.4 התקן Windows (Next, Next, Next)
    הפעל VM → לחץ מקש לאתחול מ-CD
שפה: English → Next → Install now
"I don't have a product key" → Windows 10 Enterprise → Custom install
בחר את הדיסק היחיד → Next → המתן 15 דקות
אזור: בחר שלך → "Domain join instead" → username: lab → בלי סיסמה
בטל אופציות telemetry → Cortana off → סיים
  5. 3.5 ודא Administrator
    לחיצה ימנית על Start → Windows PowerShell (Admin) → Yes
PS> whoami
     win10-lab\lab
PS> whoami /groups | findstr "S-1-16-12288"
     Mandatory Label\High Mandatory Level   Label   S-1-16-12288
זה מאשר admin token. אתה אדמין.
  6. 3.6 Snapshot לפני כל מעבדה
    תפריט VM: Machine → Take Snapshot → "clean-win10" → OK
    תמיד שחזר snapshot זה לפני הרצה חוזרת של מעבדות 2 או 3.

שלבי המעבדה

  1. שלב 1 — התקנת Volatility 3
    # Kali ברירת מחדל: Volatility 3 מותקן
# אם לא:
sudo apt install -y volatility3
# או
pip3 install volatility3

# הורדת Symbol Tables (פעם אחת)
VOL3_PATH=$(python3 -c "import volatility3, os; print(os.path.dirname(volatility3.__file__))")
mkdir -p "$VOL3_PATH/symbols"
cd "$VOL3_PATH/symbols"
wget -q https://downloads.volatilityfoundation.org/volatility3/symbols/windows.zip
unzip -q windows.zip && rm windows.zip

# בדיקה
vol --help | head -5
  2. שלב 2 — קבלת Memory Dumps
    mkdir -p ~/lab4 && cd ~/lab4

# העתקה מתיקיית הקורס
cp /opt/labs/day5/cridex.vmem .
cp /opt/labs/day5/stuxnet.vmem .

# או הורידו אותם בעצמכם — השתמשו בכתובות שבסעיף "קבלת Memory Dumps"
# למעלה (downloads.volatilityfoundation.org/volatility-memory-samples/).
# אם כתובת מחזירה 404, דף ה-wiki "Memory Samples" של Volatility הוא מקור האמת.

# בדיקה
file cridex.vmem
ls -lh *.vmem
sha256sum *.vmem
  3. שלב 3 — windows.info: זיהוי Profile
    # Vol3 מזהה Profile אוטומטית
vol -f cridex.vmem windows.info | tee output_cridex_info.txt
vol -f stuxnet.vmem windows.info | tee output_stuxnet_info.txt

# מה לזהות:
# Kernel Base
# DTB (Directory Table Base)
# Symbols
# OS version + Service Pack
    cridex.vmem: WinXP SP2 x86. stuxnet.vmem: WinXP SP3 x86.
  4. שלב 4 — windows.pslist: רשימת תהליכים
    vol -f cridex.vmem windows.pslist | tee cridex_pslist.txt

# מה לחפש:
# - תהליכים שלא אמורים להיות שם (svch0st.exe מתחזה)
# - PIDs שמופיעים פעמיים
# - תהליכים עם Parent חשוד (cmd.exe ילד של word.exe?)
# - שמות מרובי-רווחים, יוניקוד

# סינון לפי שם:
vol -f cridex.vmem windows.pslist | grep -i explorer
vol -f cridex.vmem windows.pslist | grep -i reader_sl
  5. שלב 5 — windows.psscan: זיהוי תהליכים מוסתרים
    # psscan סורק את הזיכרון לכל מבני _EPROCESS
# גם תהליכים שמסתירים עצמם דרך DKOM rootkit מופיעים כאן
vol -f cridex.vmem windows.psscan | tee cridex_psscan.txt

# השוואה: pslist vs psscan
diff <(grep -oP "\d+" cridex_pslist.txt | sort -u) \
     <(grep -oP "\d+" cridex_psscan.txt | sort -u)

# תהליכים ב-psscan ולא ב-pslist = מוסתרים = rootkit territory
  6. שלב 6 — windows.pstree: Parent-Child
    vol -f cridex.vmem windows.pstree | tee cridex_pstree.txt

# מה לחפש:
# - svchost.exe חייב להיות ילד של services.exe
# - lsass.exe ילד של winlogon.exe (XP) או wininit.exe (7+)
# - csrss.exe ילד של smss.exe
# - cmd.exe ילד חשוד (winword.exe? excel.exe?)

# חריגות = לחקור
  7. שלב 7 — windows.malfind: Code Injection
    mkdir -p output/malfind
vol -f cridex.vmem windows.malfind --dump --dump-dir output/malfind | tee cridex_malfind.txt

# מה לחפש:
# - PAGE_EXECUTE_READWRITE flags
# - MZ header (4D 5A) באמצע הזיכרון
# - PIDs עם הזרקה: explorer.exe, reader_sl.exe (ב-Cridex)

# בדיקת ה-dumps שנוצרו
ls -la output/malfind/
file output/malfind/*
sha256sum output/malfind/*
    Cridex מזריק קוד ל-explorer.exe (PID 1484) ו-reader_sl.exe (PID 1640).
  8. שלב 8 — windows.netscan: חיבורי C2
    vol -f cridex.vmem windows.netscan | tee cridex_netscan.txt

# סינון חיבורים פעילים בלבד
grep -E "ESTABLISHED|LISTENING" cridex_netscan.txt

# מה לחפש:
# - PID שאמור להיות לא-מקושר (explorer.exe לאינטרנט?)
# - IPs חיצוניים עם RAW (Tor, geo-anomaly)
# - פורטים חשודים: 4444, 8080, 1337
# - כמה חיבורים מאותו PID לאותו IP
    PID 1484 (explorer.exe) -> 41.168.5.140:8080 ו-125.19.103.198:8080 (C2 של Cridex).
  9. שלב 9 — windows.cmdline: ארגומנטים של תהליכים
    vol -f cridex.vmem windows.cmdline | tee cridex_cmdline.txt

# מה לחפש:
# - powershell -EncodedCommand ...
# - cmd /c ... (פקודות מקושרות)
# - ארגומנטים מוזרים, נתיבים זמניים, hashes/keys
  10. שלב 10 — windows.hashdump: חילוץ Credentials
    vol -f cridex.vmem windows.hashdump | tee cridex_hashdump.txt

# פלט:
# Administrator:500:LMhash:NTLMhash:::
# Guest:501:...
# User:1000:...

# שמירה לקובץ קריאה ל-Hashcat
cat cridex_hashdump.txt | awk -F: '{print $4}' > ntlm_hashes.txt
    קבצים שחולצו = ראיות. שמור hash + תעד מקור.
  11. שלב 11 — windows.dlllist: DLLs טעונים
    # הצג DLLs של PID 1484 (explorer.exe המוזרק)
vol -f cridex.vmem windows.dlllist --pid 1484 | tee cridex_dlllist_1484.txt

# מה לחפש:
# - DLLs מ-%TEMP% או %APPDATA% (לא מ-System32)
# - DLLs לא חתומים
# - DLLs עם שמות אקראיים
  12. שלב 12 — דו"ח חקירה

    בנה דו"ח לפי המבנה:

תוצאה צפויה

  • Profile זוהה אוטומטית (WinXP SP2 x86)

  • דו"ח מסכם עם Executive Summary, IOCs, MITRE

על מערכת חיה: Process Explorer = pslist+pstree, VMMap = malfind, TCPView = netscan, Process Hacker = שלם. Volatility = רק על dump (אחרי הצטלמות).

סיכום

Volatility Memory Forensics = ניתוח Memory dumps. הזיכרון מכיל את כל מה שמסתיר עצמו מ-disk: הזרקות, decrypted code, credentials, network sockets. Vol3 על Kali = workflow מהיר. כל ה-plugins הקריטיים: pslist, psscan, pstree, malfind, netscan, cmdline, dlllist, hashdump.
