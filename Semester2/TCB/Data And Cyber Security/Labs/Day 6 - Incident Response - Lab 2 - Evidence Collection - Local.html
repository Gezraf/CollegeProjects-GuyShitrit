יום 6 — מעבדה 2: איסוף ראיות

Evidence Collection — כלים מקומיים: wmic, netstat, tasklist, reg query, wevtutil, certutil
זמן משוער: 60 דקות רמה: מתקדם סביבה: Local (Windows)

מה נלמד

  • איסוף ראיות דיגיטליות (Digital Evidence Collection) באמצעות כלי מערכת ההפעלה
  • שימוש ב-wmic, netstat, tasklist לאיסוף Volatile Data
  • שימוש ב-reg query לבדיקת Persistence במערכת
  • ייצוא Event Logs עם wevtutil
  • חישוב Hashes עם certutil לאימות שלמות ראיות
  • תיעוד שיטתי עם Timestamps — שרשרת משמורת (Chain of Custody)

תרחיש האירוע

מזהה אירוע: INC-2026-0099 · תאריך: 2026-05-18 09:14 UTC

אתה אנליסט IR. התקבל דיווח מעובד שהמחשב שלו מתנהג מוזר — חלונות CMD נפתחים ונסגרים מעצמם, והמחשב איטי מהרגיל. בבדיקה ראשונית ב-AV לא נמצא דבר. עליך לאסוף ראיות ידנית מהמכונה WS-SALES-07 באמצעות כלים מובנים ב-Windows, לתעד הכל בצורה שיטתית, ולחשב hash לכל ראיה שנאספת.

חשוב: אל תפעיל מחדש את המחשב! נתונים נדיפים (Volatile Data) כמו תהליכים רצים, חיבורי רשת, וזיכרון — נמחקים בעת כיבוי/הפעלה מחדש.

אין לך גישה ל-Windows / לא Administrator?

מסלול חלופי A — אין מכונת Windows: הרץ Windows 10/11 בתוך VM חינמי (VirtualBox / VMware Workstation Player / Hyper-V). Microsoft מספקת Windows 11 Dev VM חינמי ל-90 יום: aka.ms/windowsdevvm. במחשב VM אתה Administrator כברירת מחדל.

מסלול חלופי B — אין הרשאות Admin: חלק מהפקודות עובדות גם בלי Admin (tasklist, netstat -ano, Get-Process, schtasks /query, reg query HKCU). פקודות שדורשות Admin: netstat -anob (שם תהליך), wevtutil epl Security, reg query HKLM מסוימים. עבור על המעבדה ובצע את מה שאפשר — שאר השלבים קרא בלבד.

מסלול חלופי C — אין כלום: הורד את "Sample Evidence Pack" שמספק המדריך (קובץ ZIP עם פלטים מדומים של כל הפקודות: processes_wmic.csv, netstat_full.txt, persistence_registry.txt, Security.evtx וכו'). אם המדריך לא סיפק — קרא את "פלט צפוי" בכל שלב, זה הפלט שהיית מקבל. עבור ל-Lab 3 Local שמנתח את הראיות.

דרישות מוקדמות

  • מכונת Windows 10/11 (WS-SALES-07 או מכונת Lab / VM)
  • הרשאות Administrator (מומלץ — חלק מהפקודות לא יעבדו בלי). ראה מסלול חלופי למעלה אם אין.
  • תיקייה C:\IR להכלת ראיות (ניצור בשלב 1)
  • USB drive או תיקייה רגילה לגיבוי ראיות (לא חובה אם רק מתרגל)
  • דף נייר או מסמך טקסט לרישום Chain of Custody
  • מוכנות: פתח CMD כ-Administrator (לחץ ימני על "Command Prompt" → "Run as administrator")
⚠ הערה על wmic: הכלי wmic סומן כ-deprecated מאז Windows 10 21H1 והוסר כברירת מחדל ב-Windows 11 24H2 ו-Windows Server 2025. אם הפקודה wmic לא קיימת במכונה שלך — דלג לשיטה 3 (PowerShell עם Get-CimInstance Win32_Process) שהיא התחליף המודרני. השארנו את wmic בהמשך לצורך התייחסות במכונות ישנות יותר.

שאלות למחשבה ודיון

  1. מה הסדר הנכון לאיסוף ראיות? למה אוספים תהליכים ורשת לפני לוגים ו-registry?

  3. למה svchost.exe שרץ מ-C:\Users\...\Temp\ חשוד? איפה svchost.exe אמיתי נמצא?
  4. הסבר למה אנחנו מחשבים Hash לכל ראיה. מה קורה אם ה-Hash משתנה בין האיסוף לניתוח?
  5. מה Event ID 1102 מעיד? למה חשוב לבדוק אותו?
  6. אם התוקף ניקה את ה-Event Logs — אילו ראיות אחרות עדיין זמינות?
  7. הסבר את הקשר בין ה-IOCs שמצאנו: phishing → malware → persistence → C2. מפה ל-Kill Chain.
  8. כתוב סקריפט BAT שמבצע את כל שלבי האיסוף באופן אוטומטי. מה היתרונות והחסרונות?

סיכום

איסוף ראיות ידני (Manual Evidence Collection) הוא מיומנות יסודית לכל אנליסט IR. גם כשיש כלים מתקדמים כמו EDR ו-SIEM, הידע להשתמש בכלי מערכת ההפעלה הבסיסיים — wmic, netstat, tasklist, reg query, wevtutil, certutil — הוא קריטי. במקרים רבים אלה הכלים היחידים הזמינים. המפתח: עבוד בסדר (volatile first), תעד הכל עם timestamps, חשב hash לכל ראיה, ושמור שרשרת משמורת.
