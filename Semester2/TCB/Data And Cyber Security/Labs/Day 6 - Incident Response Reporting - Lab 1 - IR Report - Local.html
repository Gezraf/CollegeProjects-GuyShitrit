יום 6 — מעבדה 1: כתיבת דוח IR

Incident Response Report Writing — Local Lab (NIST SP 800-61)
יום 6 — תגובה לאירועים ודיווח מקומי — תרגיל תיעוד קורס אבטחת סייבר — רמה מתחילה/בינונית

מה נלמד

במעבדה זו נתרגל תיעוד אירוע אבטחה מדומה לפי מסגרת NIST SP 800-61 (Incident Response). נעבוד על תרחיש של תוכנת כופר ונמלא את כל חלקי דוח IR הרשמי.

תרחיש האירוע

תרחיש מדומה בלבד! אל תבצע פעולות אלה במערכת אמיתית ללא הרשאה.

מזהה אירוע: INC-2026-0098
שם עמדה: WS-FINANCE-01
זמן גילוי: 2026-05-18 14:32 UTC (יום ב')
תיאור: תוכנת כופר זוהתה על עמדת עובד מחלקת הכספים. קבצים מוצפנים, נמצאה הודעת כופר בשולחן העבודה. וקטור ההדבקה: אימייל פישינג עם מאקרו מוסתר.

כל הנתונים בתרחיש מדומים — אין צורך במכונה אמיתית, מערכת SIEM, או הרשאות Administrator. מעבדה זו היא תרגיל תיעוד בלבד.

דרישות מוקדמות

  • עורך טקסט כלשהו (Notepad / Word / VS Code / TextEdit) — ללא צורך בהרשאות Administrator
  • דפדפן (להדפסה ל-PDF בסוף)
  • מחשבון (או טלפון) לחישוב MTTD ו-MTTC
  • תבנית דוח IR מוטמעת למטה — אין צורך בקובץ חיצוני
הערה חשובה — מבנה דוח מול שלבי NIST: NIST SP 800-61r2 מגדיר 4 שלבי IR: Preparation, Detection & Analysis, Containment/Eradication/Recovery (מקובצים), Post-Incident. דוח ה-IR להלן מפרק את ה-Containment/Eradication/Recovery לסעיפים נפרדים לצורך בהירות הדיווח — זה לא סותר את NIST. סעיף "Identification" שמופיע למטה הוא סעיף דוח, לא שלב NIST (שלב NIST מקביל = Detection & Analysis).

שלבי המעבדה

מקומי — תרגיל תיעוד
  1. שלב 1
    קריאת תרחיש האירוע

    קרא בעיון את תרחיש האירוע בסעיף למעלה. רשום לעצמך:

    • מה אירע?
    • מתי גילינו?
    • על מה זה משפיע?
  2. שלב 2
    פתיחת תבנית דוח IR

    העתק את התבנית מהחלק "תבנית דוח IR" למעלה אל עורך טקסט שלך (Notepad / Word / VS Code / TextEdit). שמור כקובץ חדש: IR-Report-INC-2026-0098.txt (או .docx).

  3. שלב 3
    מילוי סעיף 1 — גילוי (Detection) 
    תאריך ושעת גילוי:    2026-05-18 14:32 UTC
מקור הגילוי:         Antivirus Alert (Microsoft Defender) → SIEM
פרטי ההתראה הראשונית: Ransomware signature "Trojan:Win32/LockBit" detected on WS-FINANCE-01
שם חוקר ראשון:       [שמך]
  4. שלב 4
    מילוי סעיף 2 — זיהוי (Identification) 
    מערכות מושפעות:      WS-FINANCE-01 (Windows 10, Finance Dept)
היקף ההשפעה:         קבצי Office מוצפנים בתיקיית My Documents
וקטור ההתקפה:        אימייל פישינג עם קובץ Word + מאקרו זדוני
משתמש מושפע:         finance.user@company.com
  5. שלב 5
    מילוי סעיף 3 — בלימה (Containment) 
    פעולות בלימה מיידיות:
1. ניתוק WS-FINANCE-01 מהרשת (Defender → Isolate Device, או ניתוק NIC ידני)
2. השהיית חשבון finance.user@company.com (Disable, לא Delete — שמירת ראיות)
3. חסימת IOCs ב-Firewall:
   - domain: evil-ransom[.]xyz
   - IP: 185.220.101[.]10
4. שמירת disk image לצרכי ראיות (לפני כל פעולת ניקוי)
  6. שלב 6
    מילוי סעיף 4 — השמדה (Eradication) 
    פעולות השמדה:
1. הסרת קבצי הנוזקה (quarantine בוצע על ידי AV)
2. Re-image של WS-FINANCE-01 מ-Golden Image
3. עדכון Endpoint Security לגרסה אחרונה
4. חסימת סוג קבצי .xlsm ב-Email Gateway
  7. שלב 7
    מילוי סעיף 5 — התאוששות (Recovery) 
    פעולות התאוששות:
1. שחזור קבצים מ-Backup (גיבוי נקי מ-14:00 אותו יום)
2. אימות תקינות הקבצים (Hash comparison)
3. ניטור מוגבר למשך 48 שעות
4. החזרת WS-FINANCE-01 לייצור לאחר אישור
  8. שלב 8
    מילוי סעיף 6 — לקחים (Lessons Learned) 
    סיבת שורש:        משתמש לחץ על קישור פישינג ואיפשר הרצת מאקרו
תיקונים מומלצים:
1. הדרכת Security Awareness לכלל העובדים
2. הגדרת Block Macros by default ב-GPO
3. שיפור Email Filtering (Sandbox)
4. הוספת SIEM rule לזיהוי הצפנת קבצים המונית
  9. שלב 9
    חישוב מדדים

    חשב את מדדי ה-IR הבאים. שים לב להבדל בין המדדים — אנשים מבלבלים ביניהם בריאיונות עבודה.

    MTTD (Mean Time to Detect) — מזמן האירוע עד הגילוי:
  זמן האירוע:   2026-05-18 13:45 UTC (לפי לוגים)
  זמן גילוי:    2026-05-18 14:32 UTC
  MTTD = 47 דקות

MTTC (Mean Time to Contain) — מהגילוי עד סיום בלימה:
  זמן גילוי:    14:32 UTC
  סיום בלימה:   15:15 UTC
  MTTC = 43 דקות

MTTR (Mean Time to Recover/Resolve) — מהגילוי עד שיקום מלא:
  זמן גילוי:    14:32 UTC
  סיום שיקום:   17:30 UTC (אחרי שחזור מ-Backup ואימות)
  MTTR = 2 שעות ו-58 דקות

הערה: התעשייה לא תמיד אחידה — חלק קוראים MTTR ל-Mean Time to Respond (= MTTC כאן),
וחלק קוראים MTTR ל-Mean Time to Recover. הגדר במפורש בדוח שלך.
  10. שלב 10
    שמירה כ-PDF
    • Windows (Word/Notepad): File → Print → Printer: "Microsoft Print to PDF" → Print → בחר נתיב

    • VS Code / דפדפן: Cmd/Ctrl+P → Save as PDF

    שמור כ: IR-Report-INC-2026-0098-[YYYY-MM-DD].pdf

סיכום

תיעוד אירוע לפי NIST SP 800-61 הוא מיומנות קריטית לכל אנליסט SOC ו-Incident Responder. דוח IR מסודר מגן על הארגון מבחינה משפטית, מסייע בלמידה ארגונית, ומהווה ראיה בחקירות.
