מעבדת Docker — קונטיינרים בשלושה שלבים

מודול 6 — יום Linux + Docker
תאריך: 2026-05-20 זמן: כ-30 דקות רמה: ללא ניסיון קודם אתה מקליד: בטרמינל

מה זו המעבדה הזו

Docker מאפשר לך להריץ תוכנה בתוך קונטיינר — קופסה קטנה ועצמאית שמכילה כל מה שהתוכנה צריכה. אתה לא מתקין את התוכנה על המחשב שלך; אתה פשוט מריץ image מוכן מראש.

המעבדה הזו בנויה בשלושה שלבים. כל שלב קשה יותר מהקודם לו. אינך חייב לסיים את כל השלושה בכיתה — עשה כמה שאתה יכול, וסיים את השאר בבית.

  • מתחילים — כולם עושים את זה. אתה מריץ את הקונטיינרים הראשונים שלך.
  • מתקדמים — רוב האנשים מגיעים לכאן. אתה בונה image משלך ופותח אותו בדפדפן.
  • מאסטר — יעד שאיפה. אתה מריץ אפליקציית ווב אמיתית עם בסיס נתונים. סיים בבית אם נגמר הזמן.

לפני שתתחיל

המחשב שלך כבר הוכן מראש. לפני שאתה מתחיל, יש לך:

  • Docker מותקן ופועל. אינך צריך להתקין שום דבר.
  • יש חיבור לאינטרנט. הקונטיינרים יורידו מהאינטרנט.
  • טרמינל פתוח. ב-Windows זהו חלון Ubuntu (WSL2); ב-Kali/Ubuntu זוהי אפליקציית ה-Terminal.
כל פקודה במעבדה הזו כתובה בקופסה כהה. לחץ בתוך הקופסה, סמן את כל השורה, העתק אותה, והדבק אותה בטרמינל. לאחר מכן לחץ Enter. בצע שלב אחד בכל פעם.

בדיקה מהירה — האם Docker פועל? הקלד זאת ולחץ Enter:

docker info
אתה רואה שורות רבות של טקסט המתארות את Docker (Server Version, Containers, Images וכן הלאה). לא מופיעה שגיאה.
אם אתה רואה Cannot connect to the Docker daemon או permission denied, הרם את היד. Docker אינו פועל — המדריך יפעיל אותו עבורך. אל תמשיך עד ש-docker info עובד.
שלב 1

מתחילים — הקונטיינרים הראשונים שלך

כולם עושים את השלב הזה. בסופו תריץ, תרשום, תבדוק ותסיר קונטיינר.

שלב 1 — התחל קודם את ההורדות הגדולות של יום 5 (ואז המשך לעבוד)

  1. התחל את הורדת ה-image של Splunk

    המעבדות של יום 5 צריכות שני images גדולים. ה-image של Splunk הוא כ-2 GB ולוקח כמה דקות. התחל אותו עכשיו כך שיורד ברקע בזמן שאתה עושה את שאר המעבדה. הקלד:

    docker pull splunk/splunk:latest
    אתה רואה שורות כמו Pulling from splunk/splunk וכמה פסי התקדמות שמתמלאים לאט. זה ימשיך לרוץ כמה דקות — זה תקין.
  2. פתח טרמינל שני והתחל את הורדת ה-image של Volatility

    השאר את הורדת Splunk רצה. פתח חלון טרמינל חדש ונפרד (זהה לזה שיש לך). בחלון החדש, הקלד:

    docker pull sk4la/volatility3:latest
    החלון החדש מציג Pulling from sk4la/volatility3 עם פסי ההתקדמות שלו.
    עכשיו יש לך שתי הורדות רצות. השאר את שני החלונות לבדם — אל תסגור אותם. חזור לטרמינל הראשון והמשך לשלב 2. ההורדות מסתיימות לבד בזמן שאתה עובד.
    אם זה לא עבד: הודעה כמו error pulling image בדרך כלל אומרת שהאינטרנט התנתק. לחץ על חץ למעלה ו-Enter כדי להריץ את הפקודה שוב. אם זה עדיין נכשל, הרם את היד.

שלב 2 — בדוק את גרסת ה-Docker שלך

  1. שאל את Docker מה הגרסה שלו

    בחזרה לטרמינל הראשון, הקלד:

    docker version
    אתה רואה שני בלוקים של טקסט: בלוק Client ובלוק Server, כל אחד עם מספר גרסה. הופעת שני הבלוקים פירושה ש-Docker עובד במלואו.
    אם זה לא עבד: אם אתה רואה רק את בלוק ה-Client ושגיאה לגבי ה-Server, Docker אינו פועל. הרם את היד.

שלב 3 — הרץ את הקונטיינר הראשון שלך

  1. הרץ את קונטיינר הבדיקה הרשמי

    ל-Docker יש image בדיקה זעיר בשם hello-world. הרץ אותו:

    docker run --rm hello-world
    אתה רואה הודעה שמתחילה ב-Hello from Docker! ומסבירה מה בדיוק קרה. החלק --rm מוחק אוטומטית את הקונטיינר הזה כשהוא מסיים, כך שהוא לא משאיר שום דבר מאחור.
    אם זו הפעם הראשונה, Docker קודם מדפיס Unable to find image ... locally ומוריד אותו. זה תקין — זו הורדה קטנה מאוד.

שלב 4 — הסתכל על קונטיינרים ו-images

  1. רשום קונטיינרים רצים
    docker ps
    אתה רואה טבלה עם כותרות העמודות CONTAINER ID, IMAGE, STATUS וכן הלאה. כרגע כנראה אין שורות מתחת לכותרות — שום דבר עדיין לא רץ. טבלה ריקה היא תקינה.
  2. רשום את ה-images שהורדת
    docker images
    אתה רואה טבלה של images. hello-world מופיע. אם הורדות יום 5 הסתיימו, splunk/splunk ו-sk4la/volatility3 מופיעים גם הם — אם עדיין לא, זה תקין, הם עדיין יורדים.

שלב 5 — מחזור החיים של הקונטיינר: הרצה, בדיקה, עצירה, הסרה

עכשיו תריץ קונטיינר קטן של שרת ווב ותעביר אותו דרך כל מחזור חייו: התחל אותו, בדוק אותו, קרא את הלוגים שלו, עצור אותו ומחק אותו.

  1. התחל שרת ווב קטן ברקע

    פקודה זו מריצה את שרת הווב nginx. זהו image קטן. הקלד אותו במדויק:

    docker run -d --name webtest -p 8080:80 nginx

    מה משמעות החלקים: -d מריץ אותו ברקע, --name webtest נותן לו שם ידידותי, -p 8080:80 מחבר את פורט 8080 במחשב שלך לפורט 80 בתוך הקונטיינר.

    Docker מדפיס שורה ארוכה אחת של אותיות ומספרים (ה-ID של הקונטיינר) ומחזיר לך את ה-prompt. אם ה-image עוד לא הורד, אתה קודם רואה הורדה קצרה — זה תקין.
    אם זה לא עבד: שגיאה המכילה port is already allocated פירושה שמשהו אחר משתמש בפורט 8080. הרץ במקום זאת docker run -d --name webtest -p 8082:80 nginx, והשתמש ב-8082 בכל מקום שהמעבדה הזו אומרת 8080.
  2. ודא שהוא רץ
    docker ps
    הפעם בטבלה יש שורה אחת. תחת NAMES אתה רואה webtest, ותחת STATUS אתה רואה משהו כמו Up 10 seconds.
  3. קרא את הלוגים של הקונטיינר

    כל קונטיינר כותב הודעות. בקש מ-Docker להציג את ההודעות של webtest:

    docker logs webtest
    אתה רואה כמה שורות של הודעות הפעלה של nginx, המסתיימות בטקסט על start worker processes. אלו הודעות מתוך הקונטיינר.
  4. עצור את הקונטיינר
    docker stop webtest
    Docker מדפיס לך בחזרה webtest. הקונטיינר עצור עכשיו. אם תריץ docker ps שוב, הטבלה ריקה — webtest כבר לא רץ.
  5. הסר את הקונטיינר

    קונטיינר עצור עדיין קיים עד שאתה מוחק אותו. הסר אותו:

    docker rm webtest
    Docker מדפיס שוב webtest. הקונטיינר נמחק עכשיו לחלוטין.
    כדי להוכיח שהוא נעלם, הרץ docker ps -a (ה--a מציג גם קונטיינרים עצורים). webtest כבר לא מופיע בשום מקום.
שלב 1 הושלם. הרצת קונטיינרים, רשמת אותם, קראת את הלוגים שלהם וניקית. זהו תהליך העבודה היומיומי של Docker.
שלב 2

מתקדמים — בנה image משלך

רוב האנשים מגיעים לשלב הזה. תבנה image משלך משני קבצים ותפתח דף ווב משלך בדפדפן.

שלב 6 — צור תיקיית עבודה ואת שני הקבצים

תיצור שני קבצים: דף ווב (index.html) ומתכון (Dockerfile) שאומר ל-Docker איך לבנות את ה-image. שני הקבצים ניתנים לך במלואם למטה — העתק אותם במדויק.

  1. צור תיקייה ועבור אליה
    mkdir ~/mypage
cd ~/mypage
    לא מופיעה הודעה, וה-prompt מסתיים עכשיו ב-mypage. אתה בתוך התיקייה החדשה.
  2. צור את index.html

    הקלד פקודה זו ולחץ Enter. היא יוצרת את הקובץ index.html עם התוכן המדויק המוצג. העתק את כל הבלוק — מ-cat עד וכולל ה-EOF האחרון — והדבק את כולו בבת אחת:

    cat > index.html <<'EOF'
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My Container Page</title>
  <style>
    body { font-family: Arial, sans-serif; background: #2563eb;
           color: white; text-align: center; padding-top: 12vh; }
    h1 { font-size: 2.4rem; }
    p  { font-size: 1.1rem; opacity: .9; }
  </style>
</head>
<body>
  <h1>Hello from my container!</h1>
  <p>This page is being served by an image I built myself.</p>
</body>
</html>
EOF
    לא מופיעה הודעה, ואתה מקבל בחזרה את ה-prompt. הקובץ נוצר. בדוק אותו עם cat index.html — אתה אמור לראות את ה-HTML מודפס בחזרה.
    מעדיף עורך? אתה יכול גם להריץ nano index.html, להקליד או להדביק את אותו HTML, ואז ללחוץ Ctrl+O, Enter כדי לשמור ו-Ctrl+X כדי לצאת.
  3. צור את ה-Dockerfile

    ה-Dockerfile הוא המתכון. הוא אומר: התחל מ-image הקטן של שרת הווב nginx, ואז העתק את הדף שלך לתיקייה ש-nginx מגיש. הדבק את כל הבלוק הזה:

    cat > Dockerfile <<'EOF'
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/
EOF
    לא מופיעה הודעה. בדוק אותו עם cat Dockerfile — אתה רואה את שתי השורות מודפסות בחזרה.
    אם זה לא עבד: הקובץ חייב להיקרא בדיוק Dockerfile — D גדולה וללא סיומת. הרץ ls כדי לוודא שיש לך Dockerfile ו-index.html בתיקייה.

לעיון, הנה שני הקבצים המלאים שזה עתה יצרת:

index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My Container Page</title>
  <style>
    body { font-family: Arial, sans-serif; background: #2563eb;
           color: white; text-align: center; padding-top: 12vh; }
    h1 { font-size: 2.4rem; }
    p  { font-size: 1.1rem; opacity: .9; }
  </style>
</head>
<body>
  <h1>Hello from my container!</h1>
  <p>This page is being served by an image I built myself.</p>
</body>
</html>
Dockerfile
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/

שלב 7 — בנה את ה-image

  1. בנה image בשם "mypage"

    ודא שאתה עדיין בתוך התיקייה ~/mypage, ואז הקלד:

    docker build -t mypage .

    ה--t mypage נותן ל-image שלך את השם mypage. הנקודה בסוף פירושה "השתמש בקבצים בתיקייה הזו."

    Docker מדפיס כמה שלבי בנייה ומסיים בשורות כמו naming to docker.io/library/mypage ו-FINISHED. ה-image שלך נבנה.
    אם זה לא עבד: שגיאה כמו failed to read dockerfile פירושה שאתה לא בתיקייה הנכונה או ששם הקובץ שגוי. הרץ cd ~/mypage ואז ls וודא ש-Dockerfile ו-index.html רשומים שניהם.
  2. ודא שה-image קיים
    docker images
    הטבלה כוללת עכשיו שורה שבה REPOSITORY הוא mypage.

שלב 8 — הרץ את ה-image שלך ופתח אותו בדפדפן

  1. הרץ את ה-image שלך
    docker run -d -p 8081:80 mypage
    Docker מדפיס שורת container ID ארוכה אחת ומחזיר את ה-prompt. הדף שלך מוגש עכשיו על פורט 8081.
  2. פתח את הדף בדפדפן שלך

    פתח את דפדפן הווב שלך ועבור לכתובת הזו:

    http://localhost:8081
    אתה רואה דף כחול שאומר "Hello from my container!" — בדיוק הדף שכתבת ב-index.html, מוגש עכשיו מה-image שבנית.
    אם זה לא עבד: אם הדפדפן אומר שהוא לא יכול להתחבר, הרץ docker ps וודא שקונטיינר שמשתמש ב-mypage מציג Up. אם פורט 8081 היה תפוס, הרץ מחדש את שלב 8 עם -p 8083:80 ופתח במקום זאת http://localhost:8083.
  3. עצור והסר את הקונטיינר

    קודם מצא את שמו או ה-ID שלו:

    docker ps

    הסתכל בעמודה NAMES — Docker נתן לו שם אוטומטי (שתי מילים, כמו clever_morse). השתמש בשם הזה בשתי הפקודות הבאות. עצור אותו:

    docker stop NAME_FROM_DOCKER_PS

    ואז הסר אותו:

    docker rm NAME_FROM_DOCKER_PS
    כל פקודה מדפיסה בחזרה את השם. הרצת docker ps שוב מראה שהקונטיינר נעלם. ה-image mypage שלך נשאר — רק הקונטיינר הרץ הוסר.
    החלף את NAME_FROM_DOCKER_PS בשם האמיתי שראית. אתה יכול גם להשתמש באותיות הראשונות של ה-CONTAINER ID במקום השם.
שלב 2 הושלם. כתבת קבצים, בנית image משלך, וצפית בו חי בדפדפן.
שלב 3

מאסטר — אפליקציית ווב עם בסיס נתונים

השלב הזה הוא יעד שאיפה. אם נגמר לך זמן הכיתה, עשה אותו בבית — השלבים מלאים ויעבדו בעצמם.

שלב 9 — הרץ WordPress + בסיס נתונים עם Docker Compose

אפליקציות אמיתיות הן בדרך כלל יותר מקונטיינר אחד. כאן אתה מריץ שניים בבת אחת: wordpress (אפליקציית הווב) ו-db (בסיס נתונים MySQL ששומר את הנתונים שלה). במקום להקליד פקודות רבות, אתה מתאר את שני הקונטיינרים בקובץ אחד בשם compose.yaml, ו-Docker מתחיל אותם יחד.

  1. צור תיקייה חדשה ועבור אליה
    mkdir ~/myapp
cd ~/myapp
    לא מופיעה הודעה, וה-prompt מסתיים עכשיו ב-myapp.
  2. צור את compose.yaml

    הדבק את כל הבלוק הזה בבת אחת. זהו הקובץ המלא — אל תשנה שום דבר:

    cat > compose.yaml <<'EOF'
services:
  db:
    image: mysql:8.0
    restart: always
    environment:
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wpuser
      MYSQL_PASSWORD: wppass
      MYSQL_ROOT_PASSWORD: rootpass
    volumes:
      - db_data:/var/lib/mysql

  wordpress:
    image: wordpress:latest
    restart: always
    ports:
      - "8080:80"
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_USER: wpuser
      WORDPRESS_DB_PASSWORD: wppass
      WORDPRESS_DB_NAME: wordpress
    depends_on:
      - db

volumes:
  db_data:
EOF
    לא מופיעה הודעה. בדוק אותו עם cat compose.yaml — אתה רואה את הקובץ מודפס בחזרה.
    הקובץ חייב להיקרא בדיוק compose.yaml. הקטע volumes נותן לבסיס הנתונים מקום לשמור את הנתונים שלו כך שהם לא יאבדו כשהקונטיינר נעצר.
  3. התחל את שני הקונטיינרים

    ודא שאתה בתיקייה ~/myapp, ואז הקלד:

    docker compose up -d
    Docker מוריד את ה-images wordpress ו-mysql (זה יכול לקחת כמה דקות בפעם הראשונה), ואז מדפיס שורות שמסתיימות ב-Started עבור myapp-db-1 ו-myapp-wordpress-1.
    אם זה לא עבד: port is already allocated פירושו שפורט 8080 תפוס. ערוך את הקובץ (nano compose.yaml), שנה את "8080:80" ל-"8090:80", שמור, הרץ docker compose up -d שוב, והשתמש ב-8090 למטה.
  4. ודא ששני הקונטיינרים רצים
    docker compose ps
    אתה רואה שתי שורות: אחת עבור db ואחת עבור wordpress, ושתיהן מציגות סטטוס רץ.
  5. פתח את האפליקציה בדפדפן שלך

    פתח את הדפדפן שלך ועבור אל:

    http://localhost:8080
    אתה רואה את מסך ההתקנה של WordPress — הוא מבקש ממך לבחור שפה. זוהי אפליקציית ווב אמיתית, והדף שאתה רואה בנוי מנתונים השמורים בקונטיינר בסיס הנתונים MySQL לצדו.
    אם הדף לא נטען בניסיון הראשון, המתן כ-30 שניות (בסיס הנתונים צריך רגע להתחיל) ורענן. אינך חייב לסיים את התקנת WordPress — ראיית המסך היא המטרה.
  6. כבה את הכל

    כשסיימת, עצור והסר את שני הקונטיינרים בפקודה אחת:

    docker compose down
    Docker מדפיס Removed עבור שני הקונטיינרים והרשת. הרצת docker compose ps עכשיו מציגה רשימה ריקה.
שלב 3 הושלם — כל הכבוד. הרצת אפליקציה מרובת-קונטיינרים עם Docker Compose: אפליקציית ווב שמדברת עם בסיס נתונים, מותחלת ונעצרת בפקודות בודדות.

לפני שתסיים — בדוק את הורדות יום 5

זכור את שתי ההורדות הגדולות שהתחלת בשלב 1, צעד 1. עד עכשיו הן אמורות להיות מסתיימות. בדוק על ידי רישום ה-images שלך: 

docker images
הרשימה כוללת שורה עבור splunk/splunk ושורה עבור sk4la/volatility3. אם שתיהן מופיעות, המעבדות של יום 5 מוכנות לדרך.
אם זה לא עבד: אם אחד ה-images חסר, ההורדה אולי עדיין רצה או אולי נעצרה. הרץ את הפקודה החסרה שוב — docker pull splunk/splunk:latest או docker pull sk4la/volatility3:latest — והרם את היד כדי שה- מדריך יוכל לעזור לפני שמקטע יום 5 מתחיל.

רשימת הכנה למדריך

הכן כל פריט למטה על כל מחשב תלמיד לפני השיעור. המעבדה מניחה שכל זה כבר נעשה.

  • Docker מותקן ופועל על כל מחשב. ודא עם docker info — הוא חייב להחזיר פרטי שרת ללא שגיאה.
  • חשבון התלמיד יכול להריץ Docker ללא sudo (המשתמש נוסף לקבוצת docker, או ש-Docker Desktop פועל). בדוק docker run --rm hello-world כמשתמש התלמיד.
  • גישה לאינטרנט ל-Docker Hub (registry-1.docker.io) פתוחה ואינה חסומה על ידי proxy או firewall.
  • הורד מראש את ה-images הקטנים כדי שהורדות הכיתה יהיו מהירות: docker pull hello-world, docker pull nginx, docker pull nginx:alpine, docker pull wordpress:latest, docker pull mysql:8.0.
  • images של יום 5 — אל תוריד מראש את splunk/splunk:latest ו-sk4la/volatility3:latest; התלמידים מתחילים אותם בשלב 1 צעד 1 בכוונה. אבל ודא ששני שמות ה-images עדיין נמשכים בהצלחה ברשת המעבדה ביום שלפני.
  • פורטים 8080, 8081 ו-8082 פנויים על מחשבי התלמידים. הערות "אם זה לא עבד" מכסות פורטים תפוסים, אך מחשב נקי חוסך את העקיפה.
  • קל לפתוח טרמינל — Ubuntu (WSL2) על מחשבי Windows, או Terminal על Kali/Ubuntu. נעץ או הצב קיצור דרך כך שהתלמידים לא יחפשו אותו.
  • דפדפן ווב מודרני מותקן ויכול להגיע אל http://localhost.
  • מצב Docker נקי — אין קונטיינרים שנשארו בשם webtest ואין תיקיות ~/mypage או ~/myapp שנשארו מהרצה קודמת.
  • הנחיית זמן — שלב 1 מתאים לחלון הזמן בכיתה לכולם; שלב 2 לרובם; שלב 3 הוא במפורש מתיחה לעבודה בבית. אמור זאת לתלמידים מראש כדי שאף אחד לא ירגיש מפגר.
