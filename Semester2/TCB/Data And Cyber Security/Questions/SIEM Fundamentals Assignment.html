📚 סקירת המטלה

מטלה זו מכסה שני תחומי ליבה מיום 5: ניתוח נוזקות (טכניקות ניתוח סטטי, חקירת זיכרון עם Volatility) ו-יסודות SIEM (שאילתות Splunk SPL, השוואת פלטפורמות). תיישמו מיומנויות מעשיות לניתוח קבצים חשודים, פירוש פלט חקירת זיכרון, כתיבת שאילתות זיהוי, והערכת פתרונות SIEM.

זמן משוער: ~3 שעות  |  סה"כ נקודות: 100

משימה 1 — ניתוח סטטי של קובץ חשוד  (~45 דקות · 25 נק')

במעבדה זו תתרגלו מתודולוגיית ניתוח סטטי על קובץ בינארי מובנה של Windows שמותקן בכל מערכת Windows: C:\Windows\System32\mspaint.exe. התייחסו אליו כאילו היה דגימה חשודה — העתיקו אותו לתיקיית עבודה ובצעו ניתוח סטטי (אל תריצו את הקובץ מתיקיית העבודה) ותעדו את ממצאיכם בדוח מובנה.

  1. זיהוי קובץ — השתמשו בפקודת file או עורך הקסדצימלי לקביעת סוג הקובץ האמיתי. תעדו:

    • בתים קסומים (Magic bytes) — 4-8 הבתים הראשונים בהקסדצימלי
    • סוג הקובץ האמיתי מול סיומת הקובץ
    • גודל הקובץ

  2. יצירת גיבובים (Hashes) — צרו ורשמו את הגיבובים הבאים:

    • MD5
    • SHA-1
    • SHA-256

    חפשו כל גיבוב ב-VirusTotal. רשמו את יחס הזיהוי (למשל 45/72) ואת 3 שמות הזיהוי המובילים של אנטי-וירוסים.

  3. ניתוח מחרוזות — הריצו strings (או FLOSS) על הקובץ. זהו וסווגו מחרוזות מעניינות בטבלה עם עמודות:

    • ערך המחרוזת
    • קטגוריה (URL / IP / מפתח רגיסטרי / נתיב קובץ / קריפטו / API חשוד / אחר)
    • משמעות (הסבירו מדוע המחרוזת ראויה לתשומת לב)

    תעדו לפחות 10 מחרוזות מעניינות.

  4. ניתוח כותרת PE — באמצעות PE-bear, pestudio או pefile (Python), תעדו:

    • חותמת זמן קומפילציה (Compilation timestamp)
    • מספר המקטעים (Sections) ושמותיהם (למשל .text, .rdata, .rsrc, UPX0)
    • ייבואים חשודים (רשמו לפחות 5 קריאות API המצביעות על התנהגות זדונית, למשל VirtualAlloc, CreateRemoteThread, WriteProcessMemory)
    • אנטרופיה לכל מקטע (סמנו כל מקטע עם אנטרופיה > 7.0 כארוז/מוצפן ככל הנראה)
    • תוצאות זיהוי ארזן (Packer) באמצעות Detect It Easy או PEiD

  5. דוח ממצאים — כתבו דוח ניתוח סטטי בן עמוד אחד עם המקטעים הבאים:

    • תקציר מנהלים: 2-3 משפטים המתארים את הקובץ ואת הכרעתכם (זדוני/חשוד/נקי)
    • מטא-דאטה של הקובץ: טבלת גיבובים, גודל, סוג, תאריך קומפילציה
    • אינדיקטורים מרכזיים: 5 הממצאים המובילים התומכים בהכרעתכם
    • צעדים הבאים מומלצים: איזה ניתוח דינמי יש לבצע
📋 תוצר נדרש דוח ניתוח סטטי עם כל הטבלאות, ערכי הגיבוב והממצאים מתועדים.
משימה 2 — ניתוח חקירת זיכרון  (~45 דקות · 25 נק')

  3. ניתוח רשת — בדקו את פלט ה-netscan וענו:

    • אילו חיבורים חשודים ומדוע?

    • מדוע תקשורת בפורט 8080 מ-powershell.exe מדאיגה?

  4. נרטיב התקיפה — בהתבסס על כל שלושת הנספחים, כתבו ציר זמן של התקיפה המתאר מה התרחש בתחנת העבודה הנפגעת. כללו לפחות 5 שלבים כרונולוגיים מהפריצה הראשונית ועד תקשורת C2.

משימה 3 — שאילתות זיהוי Splunk SPL  (~45 דקות · 25 נק')

אתם אנליסטי SOC שמטרתכם ליצור כללי זיהוי ב-Splunk. כתבו 5 שאילתות SPL עבור התרחישים הבאים. כל שאילתה חייבת להיות פונקציונלית, להשתמש בשמות שדות ריאליסטיים, ולכלול הסבר קצר על לוגיקת הזיהוי.

  1. זיהוי Brute Force — כתבו שאילתת SPL לזיהוי ניסיונות התחברות בכוח גס. דרישות:

    • שימוש ב-Windows Security Event Log (EventCode=4625 לכניסה כושלת)
    • סף: יותר מ-10 כניסות כושלות מאותה כתובת IP מקור תוך 5 דקות
    • כללו שדות: IP מקור, חשבון יעד, ספירה, טווח זמן
    • הוסיפו בדיקת המשך לכניסה מוצלחת (EventCode=4624) מאותו IP תוך 10 דקות (המצביעה על brute force מוצלח)

  2. יצירת חשבון מנהל חדש — כתבו שאילתת SPL לזיהוי יצירת חשבון מנהל חדש. דרישות:

    • זהו EventCode=4720 (חשבון משתמש נוצר) ולאחריו EventCode=4732 (חבר נוסף לקבוצת אבטחה)
    • סננו לקבוצות: Administrators, Domain Admins, Enterprise Admins
    • התרעה אם שני האירועים מתרחשים תוך 60 שניות עבור אותו חשבון
    • אל תכללו חשבונות שירות ידועים (ציינו לפחות 3 דוגמאות לחריגות)

  3. תנועה רוחבית דרך RDP — כתבו שאילתת SPL לזיהוי תנועה רוחבית חשודה ב-RDP. דרישות:

    • שימוש ב-EventCode=4624 עם LogonType=10 (RemoteInteractive)
    • זהו מארח פנימי המתחבר ל-3 מארחים פנימיים או יותר דרך RDP תוך 30 דקות
    • אל תכללו שרתי Jump ידועים של מנהלים לפי IP
    • כללו שמות מארחים מקור ויעד בתוצאות

  4. הרצת PowerShell חשודה — כתבו שאילתת SPL לזיהוי פעילות PowerShell חשודה. דרישות:

    • שימוש ב-Sysmon EventID=1 (יצירת תהליך) או Windows PowerShell Operational Log (EventID=4104)
    • זהו פקודות מקודדות (-EncodedCommand, -enc), download cradles (IEX, Invoke-Expression, Net.WebClient, DownloadString), או ניסיונות עקיפת AMSI
    • לכדו את שורת הפקודה המלאה ותהליך האב
    • אל תכללו סקריפטים לגיטימיים לפי נתיב (למשל C:\Program Files\)

  5. זיהוי גניבת נתונים (Exfiltration) — כתבו שאילתת SPL לזיהוי גניבת נתונים פוטנציאלית. דרישות:

    • שימוש בלוגים של חומת אש או פרוקסי
    • זהו מארח פנימי בודד השולח יותר מ-500 MB החוצה ל-IP חיצוני אחד תוך שעה
    • אל תכללו כתובות IP ידועות של CDN ושירותי ענן (ספקו רשימת חריגות לדוגמה)
    • סמנו מנהור DNS: זהו שאילתות DNS עם שמות תת-דומיין ארוכים באופן חריג (> 50 תווים)
📋 תוצר נדרש 5 שאילתות SPL מלאות עם הערות מוטמעות המסבירות את לוגיקת הזיהוי, שדות פלט צפויים וספי התרעה מומלצים.
משימה 4 — השוואת פלטפורמות SIEM  (~30 דקות · 25 נק')

הארגון שלכם (500 עובדים, 3 אנשי IT, שילוב עומסי עבודה מקומיים וענן, תקציב מוגבל) צריך לבחור פלטפורמת SIEM. השוו בין שלוש האפשרויות הבאות וספקו המלצה.

  1. טבלת השוואה — צרו טבלת השוואה מפורטת עם הקריטריונים הבאים לכל פלטפורמה:

    קריטריוןSplunk EnterpriseELK Stack (Elastic)Microsoft Sentinel
    מודל רישוי
    עלות שנתית משוערת
    מודל פריסה
    עקומת למידה
    שפת שאילתות
    מודיעין איומים מובנה
    אינטגרציית SOAR
    קהילה ותמיכה
    יכולת הרחבה (Scalability)
    תמיכה Cloud-Native

  2. יתרונות וחסרונות — לכל פלטפורמה, רשמו לפחות 3 יתרונות ו-3 חסרונות הרלוונטיים לפרופיל הארגון (500 עובדים, צוות IT קטן, תקציב מוגבל).

  3. המלצה — כתבו פסקת המלצה (150-200 מילים) המציינת איזה SIEM הייתם בוחרים ומדוע. התייחסו ל:

    • עלות בעלות כוללת (TCO)
    • דרישות כוח אדם
    • אינטגרציה עם תשתית קיימת (הניחו Microsoft 365 ו-Azure AD)
    • זמן עד פריסה והגעה ליכולת תפעולית
📋 תוצר נדרש טבלת השוואה מלאה, רשימות יתרונות/חסרונות, והמלצה כתובה.
